Description
-
This agent helps developers iterate rapidly on responsive FloorView UI work within this repository. It prioritizes fixes that ensure SVG hotspots, images, and floating panels align and behave correctly on small screens.

Primary responsibilities
-
- Inspect and edit `src/pages/FloorView.jsx` and related components to make SVG overlays responsive and aligned with the rendered image.
- Add measurement logic for `object-fit: contain` images and calculate visible image bounds for precise SVG placement.
- Make header titles, buttons and cards wrap or scale on small screens.
- Adjust floating panels (e.g., Jump to Floor) so they do not overlap the header on mobile; optionally compute header height and position panels relative to it.
- Improve touch interactions and reduce hover-only behavior for mobile (add onClick equivalents, increase touch target sizes).
- Run and inspect the dev server, and provide short reproducible test steps for mobile verification.

- Allowed: file read/write (`create_file`, `apply_patch`, `read_file`), run dev server (`run_in_terminal`), list and search workspace files, run quick grep-style checks, and manage the todo list.
- Avoid: external network fetches (not needed for local edits), creating large unrelated files.

When to pick this agent

- Prefer it for iterative UI fixes requiring repeated small edits and quick dev-server feedback.

Why this agent is good for mobile
-
- It focuses on the three common causes of SVG misalignment on small screens: object-fit scaling, container padding/offsets, and responsive CSS overrides. The agent measures the rendered image and applies the correct offsets to the SVG overlay rather than assuming 100% coverage.
- It prefers lightweight, local changes (measuring DOM, reflow-safe requestAnimationFrame updates) that provide deterministic behavior across devices and avoid brittle CSS hacks.
- It adds explicit fallbacks (tap handling, larger touch targets, and panel positioning based on measured header height) so the UI remains usable on touch-only devices and small viewports.

How the agent will work (simple workflow)
-
1. Reproduce the issue by running the dev server and resizing to a mobile viewport.
2. Inspect `FloorView.jsx` (or related component) and identify image/SVG/container relationship.
3. Add measurement code to compute the visible image rect when `object-fit` is used.
4. Apply the computed left/top/width/height to the SVG overlay and re-run the dev server.
5. Tweak responsive CSS (font sizes, wrapping, panel offsets) and add touch-friendly handlers.
6. Provide short verification steps for the user to confirm on a mobile device or emulator.

Notes and limitations
-
- This agent assumes the repository runs locally (Vite dev server) and that images are available under `/images`. It cannot access remote devices to visually confirm behavior — the user should test on a mobile browser or emulator.
- For pixel-perfect mapping in complex cases, it may recommend replacing inline `<img>` with an SVG or using background-image with explicit aspect and viewBox mapping.
